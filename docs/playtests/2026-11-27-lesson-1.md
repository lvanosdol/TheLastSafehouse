## What failed, and why

| Step | Cause | Fixed? |
|---|---|---|
| **B1** Load announcement races, sometimes reads headings instead | The page's purpose was announced **on a 600 ms timer**, which collides with whatever the reader is already doing. A page introduction belongs in the page | **Yes** — the timer is gone. The introduction is now a visible paragraph a reader reaches in its own time, and nothing is announced on load |
| **B2** Tab goes to where the reader is reading, not the skip link | Same fault as B1: the timed announcement moved attention mid-load | **Confirmed fixed** on re-run |
| **B3** Safety note fold/unfold | — | Passed |
| **B4** Pressing Enter on a part says only "Collapsed"/"Expanded" | **Not a page fault.** That is how a disclosure behaves: the state is announced, then you read the content with the arrow keys. The script asked for the text to be read aloud on Enter, which no disclosure does | **Script corrected** — the step now says: press Enter, then read the content with the arrow keys |
| **B7** Summary says how many are left, not how many are right | The count only appeared once every part was placed. Counting was not enough either: the tester wanted to know **which** were right | **Revised** — every summary names the parts that are right, as well as counting them |
| **B10** The failure line is read twice | It went into the assertive live region **and** was visible, so NVDA announced it and then read the panel | **Yes** — the duplicate announcement is gone; the result panel takes focus and is read once |
| **B11** Nothing is read when it powers on | A polite live-region update with no focus change is easy to miss, and the success block was the only thing relying on it | **Confirmed fixed** on re-run: the failure is now said once, and "POWER: ON" is read when it works |

## What you found that no test could

When you exit out of the lesson, it does not hand back off to Unity. The player will no longer move. Also, the rebuild link is always visible in the "What's next" box, even before you are done with the practice.

Both were real:

- **The hand-off back to Unity depended on a single event.** If `Closed` did not arrive, the player stayed frozen.
  `BenchInteraction` now re-enables the controls whenever the host reports no window, whatever the events did.
- **The rebuild link showed from the start**, which made "practise first" optional. It now appears only once all
  eight parts are matched. The navigation link stays, for moving around while testing.

## The build needs to stop being a quiz

The tester's verdict on task 7 is that pairing parts to slots on a board is the matching task again, with
longer words. What they asked for instead:

> pick up actual components and put them into the actual computer … the spots in the computer where the
> components go could highlight for you to be able to choose a spot to put them in

That is a different interaction: **a machine you put parts into**, not two columns you pair up. It is the
first task of the next slice, not a patch on this one — the board worked, and it is the wrong shape.
